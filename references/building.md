# בניית הסוכן — הפרטים

מה שקורה אחרי הראיון, בסדר.

## 1. מאמתים לפני שבונים

לפני שאתה יוצר קובץ אחד, בדוק שלושה דברים. אם אחד מהם נכשל, עצור ואמור
לבעל העסק — אל תבנה סוכן שנשען על הנחה שגויה.

| בדיקה | איך | אם נכשל |
|-------|-----|---------|
| תיקיית התמלולים קיימת ויש בה קבצים | `ls` על הנתיב | לשאול אם הכלי באמת מייצא לשם |
| קובץ הקול קיים | `ls` | לעצור ולהפנות לשלב בניית הקול |
| **"למי אני מוכר" הוא רשימה** | לקרוא את הקובץ | להפוך לרשימה יחד איתו |
| **"מה אסור לי" קיים** | לקרוא את הקובץ | לשאול אותו ולהוסיף |
| תיקיית הדרייב נמצאה | `~/Library/CloudStorage/GoogleDrive-*/` | לשאול איפה הוא שומר דברים |
| קלוד זמין | `claude --version` | לא ניתן להמשיך |
| **חיבור גוגל דרייב פעיל** | ליצור קובץ בדיקה ולאמת שהוא בענן | להסביר איך לחבר |
| חיבור מייל פעיל | שליחת בדיקה אחת | להסביר איך לחבר |

**למה הפורמט של "למי אני מוכר" חשוב:** הסוכן שולף ממנו את פלחי הקהל
ומגוון ביניהם. פסקה חופשית מחזירה רשימה ריקה, וכל התוכן של אותו יום
ידבר לאותו אדם — **בשקט, בלי שגיאה.** זה בדיוק סוג הכשל שמתגלה חודש
אחרי, כשבעל העסק אומר "התוכן חוזר על עצמו".

**על המייל:** הסוכן שולח מהחשבון של בעל העסק עצמו, דרך החיבור שכבר קיים
אצלו בקלוד קוד. אין חשבון מרכזי, אין מפתחות להעתיק, ואין עלות לאף אחד חוץ
ממנו. אם אין לו חיבור מייל — זו שתי לחיצות בהגדרות, והסקיל מסביר לו איפה.

## 2. התיקיות

**הפלט בדרייב:**

```
<Google Drive>/סוכן-התוכן/
├── 1-חומר-גלם/
├── 2-מה-למדנו/
│   ├── כאבים.md
│   ├── שאלות-חוזרות.md
│   ├── ציטוטים.md
│   └── שפה.md
├── 3-מוכן-לפרסום/
└── 4-ארכיון/
```

**המנוע מקומי:**

```
~/סוכן-התוכן-מנוע/
├── agent.py
├── heartbeat.py
├── config.json
├── state.json
└── logs/
```

**איפה למקם — הענן הוא היעד, המחשב הוא הגיבוי.**

```
☁️ גוגל דרייב     ← הסוכן מעלה לשם ישירות. זה מה שבעל העסק פותח
💻 ~/סוכן-התוכן-מנוע/   ← קוד, config, state, לוגים, וגיבוי מקומי
```

**אל תשתמש בתיקיית דרייב מסונכרנת.** זה נראה פשוט יותר, וזו מלכודת:
התיקייה תלויה באפליקציה שרצה. אצל בעלת עסק אמיתית האפליקציה נמחקה כי
תפסה מקום בדיסק, והסוכן המשיך לכתוב לתיקייה ולדווח "נשמר" — **חודשיים,
בלי שגיאה אחת.** התוכן היה שם, הוא פשוט לא הגיע לענן.

ההעלאה נעשית דרך החיבור שכבר קיים בקלוד קוד, אותו מנגנון כמו המייל.

## 3. config.json

```json
{
  "transcripts_folder": "/Users/x/Library/CloudStorage/GoogleDrive-.../Fireflies",
  "workspace": "/Users/x/Library/CloudStorage/GoogleDrive-.../סוכן-התוכן",
  "voice_file": "/Users/x/הקול-שלי.md",
  "email": "owner@example.com",
  "drive_link": "https://drive.google.com/drive/folders/...",

  "skill_refs": "/Users/x/.claude/skills/meeting-content-agent/references",
  "claude_path": "claude",
  "run_hour": 21,
  "heartbeat_hour": 7,
  "lookback_days": 30,
  "pieces_per_meeting": 3,
  "archive_after_days": 14
}
```

ארבעת הראשונים מהראיון, `drive_link` מהשאלה הקטנה בסוף, וכל השאר ברירות
מחדל שבעל העסק לא נשאל עליהן.

## 4. state.json

```json
{
  "last_run": "2026-08-27T21:00:00",
  "processed_files": ["..."],
  "format_history": { "R1": "2026-08-25", "C3": "2026-08-26" }
}
```

**`processed_files` הוא הסינון האמיתי**, לא התאריך. ראה מלכודת 9 ב־`reliability.md`.

**`format_history` מצטבר ולא מתנקה** — הוא מה שמבטיח שהרוטציה עוברת על כל
29 הפורמטים לפני שהיא חוזרת להתחלה.

## 4ב. הלינק לדרייב

אחרי שיצרת את התיקיות בדרייב, בקש ממנו דבר אחד קטן:

> "תפתח את גוגל דרייב בדפדפן, תיכנס לתיקייה `3-מוכן-לפרסום`, ותעתיק לי
> את הכתובת מלמעלה."

זה נכנס ל־`drive_link` ב־config, והמייל היומי נותן קישור **שאפשר ללחוץ
עליו** ושנפתח גם בטלפון.

**למה לטרוח:** נתיב מקומי במייל נראה כמו קישור ואינו קישור — דפדפנים
חוסמים `file://` מתוך דף. זה נבדק, וזה מתסכל: הוא לוחץ ולא קורה כלום.

**אם הוא לא מצליח** — לא נורא, משאירים ריק. המייל ייתן מסלול קריא
("סוכן־התוכן ← 3-מוכן-לפרסום ← 27/08") במקום כתובת מתה.

## 5. הצינור הלילי

```
1. קרא state
2. סרוק את תיקיית התמלולים — חלון 30 יום אחורה
3. סנן מה שכבר טופל
4. לכל קובץ חדש:
   ├── קרא והפוך לטקסט (txt / md / json / docx / vtt)
   ├── נקה שמות → [דובר 1] / [דובר 2]      ← privacy.md
   ├── שלח לניתוח
   ├── בדוק שהפלט תקין                     ← reliability.md 5,6,7
   ├── עדכן את _מה_למדנו/
   └── מחק את המקור                        ← privacy.md
5. לכל פגישה — בחר 3 פורמטים לפי הרוטציה
6. כתוב את התכנים → שמור מקומית → **העלה לדרייב ואמת שעלה**
7. סרוק את הפלט לשמות → חסום ונסה שוב אם צריך
8. העבר ל-4-ארכיון/ מה שישן משבועיים
9. עדכן state
```

## 6. שני הפרומפטים

### פרומפט הניתוח

מקבל תמלול מנוקה, ומחזיר מבנה קבוע:

```
## על מה דיברו
## הכאבים שעלו
## השאלות ששאלו
## ציטוטי זהב של הלקוח (5-10, verbatim, בלי מקור)
## ציטוטי זהב של בעל העסק (5-10, verbatim)
## ⭐ סיפורים ודוגמאות אישיות שבעל העסק סיפר
## הבעיות שבעל העסק פותר
## איך הם מנסחים את זה — מילים וביטויים
## 4 זוויות אפשריות לתוכן
```

**למה ההפרדה בין שני הקולות חשובה:** הלקוח נותן את הכאב, ובעל העסק
נותן את התשובה. תוכן שבנוי רק על הצד של הלקוח מתאר בעיה ונגמר שם.
תוכן שבנוי רק על בעל העסק נשמע כמו הרצאה. **שניהם ביחד זה מה שעובד** —
הכאב עוצר את הגלילה, והתשובה היא הסיבה שהקורא נשאר.

והסיפורים האישיים הם החומר שהכי מהר בונה חיבור, וגם היחיד שאף אחד
אחר לא יכול להעתיק.

### פרומפט הכתיבה

מקבל: הניתוח + קובץ הקול + הפורמט מ־`formats.md` + מה שנצבר ב־`2-מה-למדנו/`.

**סדר העדיפויות כשיש התנגשות:** קובץ הקול > כללי הסודיות > מבנה הפורמט.
כלומר אם הפורמט דורש משהו שסותר את הקול של בעל העסק — הקול מנצח.

## 7. התזמון

**מק** — שני קבצי plist ב־`~/Library/LaunchAgents/`:

```
com.<שם>.content-agent.plist       21:00
com.<שם>.content-heartbeat.plist   07:00
```

אחרי היצירה: `plutil -lint` לאימות, ואז `launchctl load`.

**לינוקס** — שתי שורות ב־crontab.

**חלונות** — לא נתמך בגרסה הזו. אמור את זה מראש ולא אחרי שבנית חצי.

## 8. ההרצה מולו

הרץ עכשיו, מול העיניים שלו:

```bash
python3 ~/סוכן-התוכן-מנוע/agent.py --test
```

מצב `--test` מעבד קובץ אחד בלבד, מייצר תוכן אחד, ולא מעדכן state. זה
מספיק כדי שיראה שזה עובד, ולא שורף לו את כל התמלולים בהרצה ראשונה.

**ואז פתח את הקובץ שנוצר והראה לו.** זה הרגע שבו הוא מאמין למערכת.

## 9. אימות אחרי ההתקנה

לפני שאתה מסיים, ודא בעצמך:

- [ ] התיקיות נוצרו
- [ ] הרצת הבדיקה ייצרה קובץ אמיתי, ופתחת אותו וקראת אותו
- [ ] אין שמות בפלט
- [ ] מייל בדיקה הגיע לתיבה שלו — **שיאשר שהוא רואה אותו**
- [ ] **הקובץ שנוצר נמצא בדרייב בענן** — לא רק על המחשב. לחפש אותו
      דרך `search_files` ולוודא שהוא שם
- [ ] שני התזמונים מותקנים וטעונים
- [ ] `state.json` נכתב

**על מייל הבדיקה:** אל תסתפק ב"נשלח". שאל אותו אם הוא רואה אותו בתיבה.
מייל שנשלח לתיקיית ספאם הוא מייל שלא הגיע, וזה בדיוק סוג הדבר שמתגלה
בחודש הבא במקום בדקה הזו.
